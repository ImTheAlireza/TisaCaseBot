# ✅ چک‌لیست تست دستی — فازهای ۰ تا ۹

این تنها سندِ تستِ دستیِ پروژه است. هر بند می‌گوید **چه چیزی بفرستی**، **روی چه دکمه‌ای
بزنی** و **دقیقاً چه چیزی باید ببینی**. اگر چیزی خلافِ نوشته شد، بندِ «اگر این‌طور نشد»
می‌گوید کدام فایل را ببینی و چه چیزی را برایم بفرستی (لاگ، خروجیِ کوئری، اسکرین‌شات).

> **چطور بخوانیش:** بندها به ترتیب اجرا شده‌اند؛ ۰ و ۱ را اول انجام بده، بعد ۲ تا ۸ را
> با `TISA_DRY_RUN=yes` (بدونِ نوشتن روی سایت) بسنج، و ۹ تا ۱۲ را روی فروشگاهِ واقعی.
> هر بخشِ ۳ تا ۸ مستقل است؛ می‌توانی یک‌جا فقط یکی را بروی.
>
> **هیچ داده‌ای در این تست‌ها پاک نمی‌شود** مگر جایی که صریح نوشته شده «⚠️ روی سایت می‌نویسد».

## ۰) آماده‌سازی (یک‌بار، ۱۰ دقیقه)

1. روی سرور (یا لپ‌تاپِ تست):

   ```bash
   git clone https://github.com/ImTheAlireza/TisaPostToWP && cd TisaPostToWP
   git checkout main && git pull
   python3 -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. فایل `.env` را از روی `.env.example` بساز و **فقط** این چهار تا را پر کن:

   ```
   BOT_TOKEN=۱۲۳۴۵:_real_token_
   SUDO_IDS=<شناسهٔ عددیِ کاملِ تلگرامِ خودت>   # ۹ تا ۱۰ رقم، نه ۳ رقم
   WOOCOMMERCE_URL=https://<site>.com
   WOOCOMMERCE_CONSUMER_KEY=ck_...
   WOOCOMMERCE_CONSUMER_SECRET=cs_...
   TISA_DATA_DIR=/var/lib/tisaposttowp        # روی لپ‌تاپ: /tmp/tisa-data
   TISA_DRY_RUN=yes                           # تا بند ۹ روشن بماند
   ```

3. درِ پیش‌پرواز — باید **صفر** بدهد و هیچ ⚠️ نداشته باشد:

   ```bash
   python main.py --check-config
   ```

   ✅ باید این خطوط را ببینی: `BOT_TOKEN: set` · `sudo ids : 👑 N` · `state : <TISA_DATA_DIR>` ·
   `outbox : … (0 در صف)` · `ledger : … (0 فایل)` · `importer : … ⚠️` (این ⚠️ طبیعی است، بند ۱۱)
   و در آخر `rc=0`.

4. درِ خرابی — با توکنِ خالی **باید** غیرصفر بدهد:

   ```bash
   BOT_TOKEN= python main.py --check-config; echo "rc=$?"   # rc=1
   ```

5. `TISA_DATA_DIR` را موقتاً بردار و `--check-config` بزن: باید هشدارِ «داده‌ها داخل پوشهٔ
   کد است» بدهد. بعد برگردان.

**چرا:** همهٔ فایل‌های حالت (`roles.json`, `metrics.sqlite3`, `outbox.sqlite3`,
`learned.json`, `model_catalog.json`, `tracking_ledger.json`) از همین یک مسیر می‌آیند؛
اگر داخل پوشهٔ کد باشند، یک `git clean` یادگیری‌های فروشگاهت را می‌بَرد.

## ۱) بالا آمدن و سلامت

1. `python main.py` (یا `supervisorctl start tisabot` / `docker compose up -d`).
2. در تلگرام `/start` بفرست.

   ✅ باید کارتِ خوش‌آمد با «نقش شما: 👑 سودو» و **۱۲ دکمه** ببینی (رجیستری:
   `bot/buttons.py`): `📦 تبدیل فایل کد رهگیری` · `🗜️ فشرده‌سازی عکس‌ها` · `🆕 محصول جدید` ·
   `🔄 شارژ محصول موجود` · `🧾 آخرین محصولات` · `🔍 تست پارسر` · `🏓 Ping` ·
   `📊 وضعیت` · `🔄 ری‌استارت` · `👥 مدیریت ادمین‌ها` · `🧠 یادگیری‌ها` · `⚙️ تنظیمات`.
   `🩺 عیب‌یابی کامل`، `📥 فایل متریک‌ها` و `🏓 تست‌های تک‌تک` روی منو **نیستند** — داخل
   همان صفحهٔ `📊 وضعیت`‌اند (بند ۱۰).
3. اگر با Docker بالا آمده‌ای: `docker ps` باید `Health: healthy` نشان بدهد؛ `.env` ناقص →
   `unhealthy` (healthcheck همان `--check-config` است).
4. `- [ ]` لاگ `logs/bot.log` را باز کن: هیچ `Traceback` و هیچ هشدارِ PTB نباید باشد.

**اگر این‌طور نشد:** `bot/app.py` (رجیستری ماژول‌ها) و `bot/buttons.py` (رجیستری دکمه‌ها) —
و خروجیِ `python main.py --check-config` را برایم بفرست.

## ۲) دسترسی‌ها: یک نفر دیگر + ⚙️ تنظیمات

1. `👥 مدیریت ادمین‌ها` → «➕ افزودن ادمین» → **@username** یا شناسهٔ عددیِ دوستت را بفرست.

   ✅ باید بگوید «دعوت‌نامه صادر شد» و **همان لحظه هیچ دسترسی‌ای داده نشود**؛ در همان صفحه
   یک سطرِ «⏳ در انتظار پذیرش» با دکمهٔ «↩️ لغو دعوت» اضافه شود.
2. از اکانتِ دوستت: `/start <code>` (کد را همان صفحه نشان می‌دهد).

   ✅ دوستت ادمین می‌شود و منوی **کوتاه‌تر** می‌بیند (فقط دکمه‌های `admin=True` و روشن).
3. دوستت `📊 وضعیت` را بزند: ❌ «فقط سودو» باید بخورد (این سه تا سودو‌ماندگارند).
4. `⚙️ تنظیمات` → یک دکمه (مثلاً `🗜️ فشرده‌سازی عکس‌ها`) را خاموش کن.

   ✅ از منوی **ادمینها** حذف می‌شود، از منوی خودت (سودو) حذف **نمی‌شود**.
5. `⚙️ تنظیمات` را به‌عنوان ادمین باز کن → باید «🔒 فقط سودو» ببینی، نه لیستِ خاموش/روشن.
6. `👥 مدیریت ادمین‌ها` → «➖ حذف ادمین» → تأیید → لیست به‌روز شود و `/roles` (اگر لاگ
   چت را بسته‌ای، `data/roles.json`) فرد را نداشته باشد.

**چرا:** افزودنِ ادمین «بی‌صدا» یکی از شش باگِ امنیتی فاز ۰ بود؛ امروز دعوت دو‌مرحله‌ای است
و لغوشدنی.

## ۳) 📦 تبدیل فایل کد رهگیری (فاز ۰ و ۷)

فایل تست را با این اسکریپت بساز (روی همان ماشین):

```bash
python - <<'PY'
import pandas as pd
pd.DataFrame({
    "کد سفارش": [306176, 778899, ""],
    "کد رهگیری": [1.93e23, "610001573845123456789012", "BR123456789IR"],
}).to_excel("/tmp/tracking-bad.xlsx", index=False)
PY
```

1. `📦 تبدیل فایل کد رهگیری` بزن، فایل `/tmp/tracking-bad.xlsx` را بفرست.

   ✅ باید این‌ها را ببینی، به‌همین ترتیب:
   - همان اول (قبلِ فرستادن فایل) یک خطِ `🚧` با سقف‌ها: حجم فایل، تعداد ردیف، زمانِ پردازش
     (`_limits_line()` — همان‌ها که در `.env` می‌گذاری);
   - خلاصه با خطِ 🚫: ردیف‌هایِ بارکد‑خراب **شمرده** شوند؛
   - فایلِ `tracking.csv` (ستون‌های `order_id,tracking_code`) ضمیمه شود؛
   - `needs-review.xlsx` **و** `needs-review.csv` بیایند (اکسل برای اصلاحِ دستی، CSV برای
     سیستم);
   - `problems.csv` برای سطرهای بی‌کد/تکراری.
2. `tracking.csv` را باز کن (خروجیِ موردِ انتظار):

   | ردیف | نتیجه |
   |---|---|
   | 306176 | کد رهگیری **خالی** (عددِ ساختگیِ `1.93E+23` به فایل وارد نمی‌شود) |
   | 778899 | کد ۱۹ رقمی نامعتبر → **خالی** (مگر `BARCODE_LENGTHS` را عوض کرده باشی) |
   | ردیفِ بی‌کدِ سفارش | در `problems.csv` با ذکرِ ردیف، و **در CSV نمی‌آید** |

   - [ ] چک کن `192999999999999989514240` **هیچ‌جا** در CSV نباشد — این باگِ P0-1 بود.
3. همان فایل را با سرستونِ مبهم بساز و بفرست:

   ```bash
   python -c "import pandas as pd; pd.DataFrame({'a':[1],'b':['6100015738451234567']}).to_excel('/tmp/ambiguous.xlsx', index=False)"
   ```

   ✅ باید **سؤال** بپرسد و سؤالش **دکمه** داشته باشد («کدام ستون کد سفارش است؟» با یک
   ردیفِ دکمه برای هر ستونِ محتمل) و تا انتخابِ تو **هیچ فایلی** نسازد. اگر فایلی آمد،
   آن تستِ «schema مبهم → بدونِ فایل» شکسته است. بعد از انتخاب، با همان فایلِ اصلاح‌شدهٔ
   `needs-review.xlsx` مسیر را تمام کن: فایلِ برگشتی هم باید پذیرفته شود (نه «فرمت ناشناخته»).
4. سقف‌ها را بسنج:

   ```bash
   MAX_FILE_MB=1 MAX_ROWS=2 PROCESS_TIMEOUT_SECONDS=1 python main.py   # با .env فعلی
   ```

   ✅ فایلِ بزرگ‌تر از ۱ مگ → پیامِ «خیلی بزرگ است، سقف ۱ مگ» + پیشنهادِ تقسیم؛
   فایلِ ۳ ردیفی → پیامِ سقفِ ردیف؛ هر دو **بدونِ کرش** و ربات زنده بماند.

   ```bash
   WORKER_MEMORY_MB=64 python main.py   # سقفِ حافظهٔ کارگر را عمداً تنگ کن
   ```

   ✅ یک فایلِ **کوچک** (چند کیلوبایت) → پیامِ «حافظهٔ پردازشِ ربات پر است… `WORKER_MEMORY_MB`
   را بالا ببر … `ulimit -v`»، نه `MemoryError`ِ خام؛ و در `logs/bot.log` خطِ
   `worker memory: baseline … + budget … → cap …, headroom …` نوشته شده باشد.
5. همان فایل را با جداکنندهٔ «;» (و یکی با کدگذاری utf-16) بفرست:

   ```bash
   python - <<'PY'
   import csv
   with open("/tmp/tracking-semi.csv", "w", encoding="utf-16", newline="") as f:
       w = csv.writer(f, delimiter=";")
       w.writerow(["ردیف", "بارکد", "نام گیرنده", "کد سفارش"])
       w.writerow([1, "610001573845123456789012", "امیر 123456", "123456"])
   PY
   ```

   ✅ باید همان `tracking.csv` درست را بدهد (قبلاً «ستون بارکد پیدا نشد» یا «خطا در
   پردازش» می‌داد) و در خلاصه بنویسد جداکننده‌اش «;» بوده. یک فایلِ خرابِ دست‌ساز
   (`printf 'PK\\003\\004junk' > /tmp/half.xlsx`) بفرست: ✅ جملهٔ فارسیِ «خراب یا نصفه
   دانلود شده» + راه‌حل، نه متنِ انگلیسیِ pandas. PDF را هم یک‌بار با حاشیهٔ متفاوت چاپ کن
   (یا در PDF چاپی، فایل را با پرینترِ دیگر بگیر): ✅ همان ردیف‌ها خوانده شوند، نه
   «ساختار PDF شناخته نشد».
6. `/cancel` وسطِ فلو → منو برگردد و پیامِ «لغو شد» بیاید (نه سکوت).

**اگر این‌طور نشد:** `bot/services/processor.py` (`_analyze` و `build_csv`) و
`bot/services/barcodes.py`؛ و `problems.csv` کنارِ فایلِ خروجی را برایم بفرست.

   عکسِ گرفته‌شده با موبایل) بفرست.

   ✅ عکس‌های JPEG برگشتی **کوچک‌تر** باشند و در پیام یک خطِ «X مگ → Y مگ (Z٪)» بیاید؛

3. یک فایل غیرتصویری (مثلاً `pdf`) بفرست: ✅ پیامِ «فقط jpg/png/webp» و همان لحظه از فلو
   بیرون نیفتی.
4. `IMAGE_QUALITY=40` در `.env` بگذار، ری‌استارت کن، دوباره بفرست → فایل **کوچک‌تر** و
   کیفیتِ محسوس‌اً پایین‌تر. `IMAGE_QUALITY=200` → ربات **کرش نمی‌کند**، به ۱۰۰ clamp می‌شود

**چرا:** فشارِ تصویر در همان `bot/services/image_compressor.py` انجام می‌شود که مسیرِ محصول
هم استفاده می‌کند؛ یک رگرسیون اینجا یعنی تصویرِ محصول روی سایت هم خراب می‌شود.

## ۵) 🆕 محصول جدید — مسیرِ اصلی (فاز ۲، ۳، ۵، ۶، ۹)

این مهم‌ترین بندِ چک‌لیست است. زیر‌بندهایش را به‌ترتیب برو؛ هر کدام یک باگِ واقعیِ
گزارش‌شده را می‌پاید. برای همه، `TISA_DRY_RUN=yes` باشد (هیچ چیز روی سایت نمی‌نشیند).

### ۵.۱ ورودِ ساده + قیمتِ درست

1. `🆕 محصول جدید` → ✅ **فقط یک** پیامِ راهنما می‌آید («عکس‌های محصول را بفرست…»)
   و تنها دکمه‌اش «❌ لغو» است. این پیام باید تا پایانِ جریان دست‌نخورده بماند — با
   رسیدنِ عکس یا متن نه ویرایش شود، نه پاک، نه جابه‌جا.

   **آلبوم** دو عکس بفرست با کپشن:

   ```
   قاب سیلیکونی مگنتی آیفون 13 پرو
   ```

2. تا معطل نمانی: به‌محضِ رسیدنِ همین آلبوم باید یک کارتِ پیش‌نمایشِ تازه **زیرِ**
   عکس‌ها بیاید (پیامِ راهنما دست‌نخورده)، و هرچه استخراج جلو برود همان کارت
   مرحله‌به‌مرحله پر شود — اول عنوان/شناسه/قیمت/موجودی از متن خودت، بعد مدل‌ها،
   بعد ویژگی‌ها و دسته‌بندی. «✅ تصاویر تمام شد» دیگر وجود ندارد؛ تایمرِ آلبوم
   خودش پردازش را شروع می‌کند.

3. بعد از پیامِ راهنما، این را بفرست:

   ```
   قیمت: ۶۹۸ت
   ```

   ✅ کارتِ پیش‌نمایش.

   ✅ رفتارِ «همیشه پایین»: بعد از هر پیامِ خودت (متن یا عکس)، کارتِ پیش‌نمایشِ قبلی
   ناپدید می‌شود و کارتِ تازه **زیرِ همان پیام** می‌آید؛ در چت هیچ‌وقت دو پیش‌نمایش
   زنده نباشد. با کلیکِ دکمه‌ها (مثل «✏️ اصلاح فیلد خاص») کارت سرجایش ویرایش می‌شود و
   پیام تازه‌ای نمی‌آید.

   ✅ خطا هم پیامِ تازه نمی‌سازد: برای دیدنش یک عکسِ خراب/غیرقابل‌پردازش بفرست →
   کارت دست‌نخورده می‌ماند و فقط یک واکنشِ گذرای ⚡ روی همان عکس می‌آید (شرحِ فنی
   در گروه لاگ).

   ✅ **اندو (برگرداندن به حالت قبل):** یک اصلاحِ بد بفرست که کارت را خراب می‌کند
   (مثلاً `قیمت ۱۲۰`) → کارتِ غلط را ببین → روی «↩️ برگرداندن به حالت قبل» بزن.
   باید همان کارت، سرِ جایش، به پیش‌نمایشِ **قبلی** برگردد؛ پیام تازه‌ای نیاید؛ فقط یک
   توستِ «↩️ به حالت قبل برگشت» بیاید؛ و متنِ خراب از «اطلاعات محصول» هم بیرون رفته
   باشد (بعد از undo، اگر همان متن دوباره خوانده شود نباید برگردد). یک بار دیگر بزن →
   یک قدمِ عقب‌تر. دکمه وقتی تاریخچه خالی است نباید دیده شود.

   ✅ باید این را ببینی (نه بیشتر، نه کمتر):
   - `عنوان: قاب سیلیکونی مگنتی آیفون 13 پرو`
   - `قیمت: 698,000 تومان`
   - `مدل‌ها (1): iPhone 13 Pro`
   - `تعداد variation: 1` و زیرش هیچ ⚠️ نبودِ ویژگی نباشد… **اگر** فقط یک مدل باشد،
     کارت باید صادقانه بگوید «محصول simple ساخته می‌شود».

### ۵.۲ دو قیمت در دو پیام (خطای رایجِ فروشندگان)

1. کپشن + این متن:

   ```
   قیمت ایفون 698 اندروید 598
   ```

   ✅ `قیمت:` باید دو گروه نشان بدهد: `iphone: 698,000 | android: 598,000` (و پایه). اگر
   فقط یکی آمد یا قیمتِ سامسونگ = قیمتِ آیفون شد، P0-4 برگشته است.
2. دو قیمت در **دو پیام** مختلف بفرست (`قیمت ۱۰۰۰۰۰` بعد `قیمت ۱۲۰۰۰۰`) → پیامِ آخر برنده
   است (این رفتارِ مستندِ «اصلاحات append» است).

### ۵.۳ «وزن ۲۵۰ گرم» قیمت نمی‌شود

1. این متن را بفرست:

   ```
   قیمت: ۶۹۸ت
   وزن 250 گرم
   1403/01/01
   کد ملی 1234567890
   ```

   ✅ در کارتِ پیش‌نمایش `قیمت: 698,000 تومان` **بماند**. هیچ‌کدام از ۲۵۰٬۰۰۰ / ۱٬۴۰۳ /
   ۱٬۲۳۴٬۵۶۷٬۸۹۰ جای قیمت را نگیرند.
2. دامنه را بسنج: `قیمت ۹ تومان` → ✅ کارت باید هشدارِ بیرون‌بودنِ بازه بدهد
   (`PRICE_MIN=1000`) و عددِ ۹ تومان **ارسال نشود**؛ و `قیمت ۹۰۰۰۰۰۰۰۰` هم همین‌طور.

### ۵.۴ قیمت ویژه (تخفیف) — باگِ فاز ۹

1. به‌ترتیبِ معمول و با این متن:

   ```
   قیمت 500000
   قیمت ویژه 420000
   ```

   ✅ `قیمت: 500,000 تومان` و `قیمت ویژه: 420,000 تومان (…)`.
2. جای دو خط را **عکس** کن (`قیمت ویژه 420000` اول، `قیمت 500000` بعد): ✅ نتیجه باید **همان**
   باشد. (این دقیقاً همان باگی است که خطِ ویژه، قیمتِ اصلی را می‌بلعید.)
3. تخفیفِ معکوس بده: `قیمت 100000` و `قیمت ویژه 498000` → ✅ روی کارت پیام
   «قیمت ویژه (۴۹۸٬۰۰۰ تومان) از قیمت اصلی کمتر نیست» ظاهر شود و **تأیید متوقف نشود** —
   فقط هشدار. اگر خطا داد و هیچ توضیحی نداد، آن کارت بی‌صداست.

### ۵.۵ موجودی / ناموجود / پیش‌فروش

برای هر کدام یک محصولِ تازه بساز (دکمهٔ «➡️ مورد بعدی» یا شروعِ دوباره):

| متنِ ارسالی | ✅ انتظار در کارت |
|---|---|
| `موجودی ۲۰ عدد` | `موجودی: 20 عدد (روی خود محصول)` — و اگر محصول واریабل است: `روی هر N واریژن` |
| `ناموجود` | `موجودی: ناموجود` و عنوان محصول **خالی** بماند (باگِ فاز ۹: «ناموجود» نامِ محصول می‌شد) |
| `تمام شد` | مثل بالا، ناموجود |
| `پیش‌فروش` | وضعیت `onbackorder` («سفارش پس‌ازموجودی») |
| `۰ عدد` بدونِ کلمهٔ «موجودی» | موجودی **None** باشد (یعنی «نگفت»، نه «صفر») |

### ۵.۵.۱ قیمت مدل‌محور و قیمت همکاری

متن اطلاعات محصول (با کپشنی که مدل‌های سری ۱۷ و ۱۶ را دارد):

```
قیمت سری ۱۷ میشه ۵۹۸
قیمت سری های دیگه ۴۹۸

قیمت همکاری
سری ۱۷ میشه ۴۴۸
باقی سری ها ۳۹۸
```

| ✅ انتظار در کارت |
|---|
| `قیمت: 498,000 تومان` به‌عنوان قیمت پایه (بقیهٔ سری‌ها) |
| `قیمت مدل‌های خاص: iPhone 17: 598,000 | iPhone 17 Pro: 598,000` |
| `قیمت همکاری (فقط ثبت، در سایت اعمال نمی‌شود): پایه: 398,000 | iPhone 17: 448,000 | …` |
| `⚠️ حدسی: قیمت مدل‌های خاص، قیمت همکاری` — چون نگاشت سری به مدل کار AI است |
| بعد از تأیید: واریژن هر مدل قیمت خودش را دارد؛ بقیه مدل‌ها `498,000` |

موارد منفی (هر کدام باید **قبل از ساخت** با ⛔ بایستد، نه با قیمت حدسی):
`قیمت سری ۱۷ ۵۹۸` بدون ذکر بقیه (AI نگاشت نداده) · `قیمت ویژه سری ۱۷ ۵۹۸`
(تخفیف سری‌محور) · مدلی که نه override دارد نه قیمت پایه · ساخت ZIP برای این قیمت‌ها.

### ۵.۹ ژورنال: یک کارت، نه چهارده پیام

✅ بعد از تأیید، **یک** پیامِ جمع‌وجور ببینی با خطوطِ: عنوان، `product_id`/پیامِ dry-run،
`⏱ N ثانیه`، تعداد واریژن، تعداد تصویر، و اگر چیزی ناقص بوده **همان‌جا** ⚠️.
هیچ‌کدام از اعداد «۰» نباشند مگر واقعاً صفر فرستاده شده باشد (۰ واریژن یعنی فروشگاه صفر
واریژن گرفت؛ اگر جریانی به آن مرحله نرسیده، باید `—` باشد).

- [ ] با `LOG_CHAT_ID` تنظیم‌شده: گزارش ساخت فقط در گروه لاگ بیاید؛ dry-run صریحاً بگوید
      هیچ درخواستی به سایت نرفته و انتشار واقعی صریحاً بگوید درخواست‌ها ارسال شده‌اند.
      هیچ trace فنی به پیوی/چت شروع‌کننده نرود.
- [ ] `VERBOSE_LOG=yes` + ری‌استارت → علاوه بر کارت و گزارش HTTP، trace کاملِ گام‌های
      جریان بعد از کارت به گروه لاگ بیاید. با `VERBOSE_LOG=no` فقط trace HTTP انتشار
      (نه تمام گام‌های جریان) در گروه باشد؛ trace محلی هم در `logs/bot.log` بماند.

## ۶) ✏️ اصلاح فیلد، یادگیری خودکار (فاز ۶) و پنل 🧠

1. در صفحهٔ پیش‌نمایش «✏️ اصلاح فیلد خاص» → «قیمت» → مقدارِ درستِ `۷۱۲۰۰۰` را بنویس → ✅

   ✅ سه چیز را یک‌جا ببینی: متنِ قبل، متنِ بعد، و «این قاعده روی ۸ استخراجِ آخر چه می‌کرد»

   اصلاحاتِ خودِ ادمین‌ها را نشان بدهد. بعد از هر عمل، پیامِ تأیید با عددِ به‌روزِ قوانین

5. همان قیمتِ اشتباه را در یک محصولِ **دیگر** دوباره بفرست (بدونِ اصلاح) → ✅ اگر قاعده را

   نکند؛ «بله» `data/learned.json` را خالی کند و صفحهٔ لیست بگوید «قانونی نیست».
7. پنل را با حسابِ **ادمین** بزن → ❌ رد. (یادگیری فقط سودو.)

**اگر این‌طور نشد:** `bot/services/learning.py`, `learning_impact.py`,
`learning_corpus.py` + محتوای `data/learned.json`.

## ۷) 🔄 اپدیت محصول موجود

> دو بار انجامش بده: یک‌بار با `TISA_DRY_RUN=yes` (محصول «دمو»؛ هیچ چیز روی سایت نمی‌رود) و
> یک‌بار با `no` **روی یک محصولِ تست** (نه محصولِ اصلی). جزئیات قواعد: `docs/UPDATE-FLOW.md`.

1. `🔄 اپدیت محصول موجود` → SKU دقیق یا بخشی از عنوان را بفرست (در dry-run: «دمو»).

   ✅ جست‌وجو فقط «typing…» نشان بدهد (پیامِ «دنبال می‌گردم» نباشد)؛ فهرست با «🔎 جستجوی
   دوباره» و «⏹ انصراف»؛ محصول‌های اخیرِ خودت دکمه‌اند؛ اگر چیزی پیدا نشد، صفحه بگوید چه
   جست‌وجو شد. یک عکس بفرست: ✅ فقط ⚡ روی همان پیام (پیام تازه نه).
2. یک کاندید را بزن.

   ✅ **همان پیامِ فهرست** به «پیام راهنما» تبدیل شود (پیام تازه نه): عنوان، `#id`، SKU، تعداد
   واریژن/تصویر، مدل‌ها و رنگ‌ها، قیمتِ فعلی؛ فقط دکمهٔ «❌ لغو» دارد؛ و با رسیدنِ عکس/متن
   **ویرایش نمی‌شود**.
3. (الف) دو عکس + کپشنِ هر مدل در یک خط (`iPhone 13 Pro Max` / `iPhone 15`) + `قیمت 720000 تومان`
   + `موجودی 12` بفرست.

   ✅ کارت مرحله‌به‌مرحله پر شود (اول قیمت/موجودی/عکس، بعد مدل‌ها)؛ با هر پیامِ تازه کارتِ قبلی
   پاک شود و جدید پایینِ چت بیاید؛ **فقط تفاوت‌ها** با `←` دیده شود (`698,000 ← 720,000`، `0 ← 12`،
   `🖼 2 تصویر جدید جای 3 تصویر فعلی`، `➕ iPhone 15`، `🗑 S24 Ultra`)، یک ردیفِ
   `♻️ واریژن‌ها: همهٔ 3 واریژن فعلی پاک می‌شوند و N ترکیب از نو ساخته می‌شود`، و آخرش
   «✓ دست‌نخورده: …». تا اینجا **هیچ نوشتنی** روی سایت نرفته باشد.
4. (ب) فقط `موجودی 12` بفرست (قیمت نه).

   ✅ کارت ردیفِ قیمت نداشته باشد و «قیمت» در «دست‌نخورده» باشد؛ بعد از اعمال، قیمت‌ها در سایت
   همان قبلی بمانند.
5. (ج) `سلام` (یا هر خطِ بی‌برچسب) بفرست.

   ✅ عنوان **عوض نشود**؛ کارت بگوید «از متن «سلام» به‌عنوان عنوان برداشت شد ولی دست
   نمی‌خورد؛ … بنویس «عنوان: …»». با `عنوان: قاب مگنتی` ✏️ ردیفِ عنوان بیاید.
6. «✏️ اصلاح فیلد خاص» → ✅ فهرست **SKU / دسته‌بندی / قیمت همکاری** را نداشته باشد. «↩️ برگرداندن»
   → ✅ کارتِ قبلی در همان پیام برگردد.
7. `قیمت ویژه` بیشتر از قیمت بنویس → ✅ ⛔ روی کارت و toast هشدار با «✅ اعمال تغییرات»؛ چیزی نوشته نشود.
8. «✅ اعمال تغییرات».

   ✅ **همان کارت** به «🔄 محصول به‌روز شد + تغییرها» تبدیل شود (پیام تازه به چت فروشنده نرود)؛ در
   سایت: **همهٔ واریژن‌های قبلی پاک شده و کلِ ترکیب‌ها از نو ساخته شده** (حتی برای مدلی که در فهرست
   ماند: شناسه‌اش عوض شده)، فهرست‌های مدل/رنگ همان‌هایی که فرستادی، گالری با همان عکس‌های تازه؛
   قیمت، قیمت ویژه، موجودی و عکسِ واریژنِ هر ترکیبِ قبلی — اگر چیزی ننوشتی — **همان قبلی** باشد.
   در گروه لاگ **دو پیام**: کارت «🔄 محصول اپدیت شد» و ردپای HTTP — و در چتِ فروشنده هیچ ردپایی
   نباشد. در dry-run نتیجه «🧪 تست موفق؛ چیزی در سایت عوض نشد» و لینکِ ویرایش ندارد.
9. فروشگاهِ تغییرکرده: بعد از دیدنِ کارت، در وردپرس قیمتِ یک واریژن را دستی ۷۲۰٬۰۰۰ کن و بعد
   «✅ اعمال تغییرات» را بزن.

   ✅ چیزی نوشته نشود؛ همان کارت با «⚠️ فروشگاه از آخرین بررسی عوض شده…» و عددهای تازه برگردد؛ بار
   دوم تأیید، همان را بنویسد.
10. (د) **فهرستی که همان فهرستِ فروشگاه است** (همان مدل‌ها، فقط `قیمت 720000 تومان`) بفرست.

    ✅ ردیفِ «♻️» نیاید؛ بعد از اعمال شناسهٔ واریژن‌ها **عوض نشده** و فقط قیمت درجا نوشته شده باشد.
    (ترتیبِ فهرست یا املای دیگرِ همان مدل — «ProMax» به‌جای «Pro Max» — هم بازسازی نمی‌سازد.)
    (هـ) فقط فهرستِ مدل بفرست، **بدون قیمت و موجودی** → ✅ بعد از اعمال، واریژن‌ها از نو ساخته شوند
    ولی قیمت/موجودی/عکسِ هر ترکیبِ قبلی همان باشد؛ مدلِ تازه قیمتِ فعلیِ گروهش را بگیرد و کارت
    هشدار بدهد «قیمت/موجودی واریژن‌های تازه را ننوشتی».
11. نوشتنِ نیمه‌کاره (فقط روی تستی که می‌توانی ساختِ واریژن را رد کنی؛ در غیر این صورت از تست‌های خودکار
    `tests/test_update_flow.py` و `tests/test_update_apply.py` بگذر): ✅ «⚠️ بخشی اعمال شد: …» روی
    کارت، قدیمی‌ها **حذف نشده**، و دوباره زدنِ دکمه شبکه را کامل کند: هیچ ترکیبی دوبار نباشد، مدلِ تازه
    که نیمه‌ساخته مانده بود هر رنگش را بگیرد، و عکسِ آپلودشده تکرار نشود.
12. وسطِ فلو `🆕 محصول جدید` را بزن → ✅ فلوی اپدیت بسته شود و «جریانِ قبلی بسته شد» بیاید (دو فلو
    هم‌زمان روی یک چت مجاز نیست). «اپدیت محصول بعدی» روی کارت نتیجه → ✅ جست‌وجو **زیر** کارت
    بیاید و خودِ کارت دست نخورد.
13. روی یک محصولِ **ساده** (بدون مدل) فقط قیمت/موجودی بفرست → ✅ روی خودِ محصول بنشیند؛ مدل و
    رنگ بفرستی → ⛔ «محصول ساده است…» و چیزی نوشته نشود.

3. ورودیِ خالی بفرست → ✅ پیامِ «چیزی برای خواندن نبود» + دکمهٔ بازگشت.

## ۹) نوشتن روی ووکامرس: صف، idempotency، تصاویر (فاز ۴)

> از اینجا به بعد `TISA_DRY_RUN` را `no` بگذار و **روی یک فروشگاهِ تست** (نه فروشگاهِ اصلی)
> یا روی یک دستهٔ بدونِ رفرنس کار کن.

1. `TISA_DRY_RUN=no` + ری‌استارت. یک محصولِ کامل بساز (مثل ۵.۱، یک آلبومِ ۲ عکسی).
   ✅ در ووکامرس: محصولِ `draft` با همان عنوان، `menu_order` تصاویر ۰..n-1، تصویرِ واریژن
   **فقط** جایی که نامِ رنگ با نامِ فایل/کپشن می‌خواند.
2. تکرارِ همان ارسال: همان محصول را دوباره با «✅ تأیید و ساخت» بفرست (بدونِ هیچ تغییر).
   ✅ محصولِ تکراری **نساخته** شود (`batch_id` یکی است) و پیامِ «این قبلاً ارسال شده»
   را ببینی.
3. **قطعیِ شبکه** را شبیه‌سازی کن: `WOOCOMMERCE_URL=https://127.0.0.1:9` → محصول بساز →
   «✅ تأیید و ساخت».

   ✅ پیامی که **کلمه‌به‌کلمه** این است:
   «🐇 این خطا موقتی است؛ در صفِ تلاش مجدد گذاشتمش (۷ بار دیگر، تا ۲۴ ساعت، بدون اینکه کاری
   کنی) و نتیجه را همین‌جا می‌گویم.»
   - [ ] `sqlite3 data/outbox.sqlite3 "select batch_id,attempts,status,next_at from outbox"`
         → یک ردیف `pending` با `attempts=1`، و `last_error` که متنِ خطا را نگه داشته؛
   - [ ] بعد از ~۶۰ ثانیه تلاشِ دوباره؛ فاصله‌ها دو‌برابر می‌شوند و سقفِ ۳ ساعت رعایت می‌شود
         (در `logs/bot.log`: `outbox: تلاش 2/8 برای …`)؛
   - [ ] هر ۸ تلاش که برود، ردیف **پاک نمی‌شود** — `status='dropped'` می‌گیرد و در چت
         «❌ بعد از N تلاش این محصول در صف ماند و رها شد: … دوباره «تأیید و ساخت» را بزن»
         می‌آید (شکست هم گزارش می‌شود، نه اینکه آروم غیب شود).

4. `WOOCOMMERCE_URL` را درست کن → ✅ تلاشِ بعدی موفق شود، ردیف از صف **پاک** شود و کارتِ
   محصولِ نهایی ارسال شود.
5. دادهٔ غلط بفرست تا Woo با **۴۰۰** جواب بدهد (مثلاً دسته‌بندیِ ناموجود، یا عنوانِ خالی را
   با «✏️ اصلاح فیلد خاص» خالی بگذار و تأیید کن).

   ✅ برای ۴۰۰ **هیچ ردیفی در صف نمی‌نشیند** (تلاشِ دوباره همان جواب را می‌گیرد) و پیامِ
   خطا با متنِ خودِ ووکامرس می‌آید. اگر بعداً یک ردیفِ صف‌شده با ۴۰۰ جواب داد، پیامش این است:
   «❌ تلاشِ صف‌شده نشد، چون خطای تکراری است (HTTP 400) … این را باید دستی درست کنی؛ صف
   دیگر برایش تلاش نمی‌کند.»
6. `📊 وضعیت` باید صف را بشمارد («… در صف») و بعد از موفقیت «۰ در صف» نشان بدهد؛
   فایل‌های تصویرِ صف در `data/outbox_files/` باشند. فایل‌های تصویریِ صف در `data/outbox_files/`
   باشند و بعد از موفقیت پاک شوند.

**چرا:** ۴۰۰ و ۵۰۰ دو دنیای متفاوت‌اند؛ اشتباهِ این دو یعنی یا پیامِ گم‌شده، یا ۸ بار کوبیدن
به درِ یک API که داده را رد کرده.

## ۱۰) 📊 وضعیت، 🩺 عیب‌یابی، متریک‌ها (فاز ۸)

1. اینترنت/سایت را قطع کن (یا `WOOCOMMERCE_URL` را خراب کن) و `📊 وضعیت` بزن.

   ✅ صفحه **باید پر شود** — هیچ درخواستِ شبکه‌ای در آن نیست. چک کن این‌ها باشند:
   نسخهٔ ربات، پایتون، dry-run روشن/خاموش، `state : <مسیر>`، دیسک آزاد، تعداد سودو/ادمین،
   `LOG_CHAT_ID` (+ «یعنی چه چیزی را نمی‌فرستم»), `MAX_FILE_MB/MAX_ROWS/PROCESS_TIMEOUT_SECONDS`,
   صفِ ارسال، دو دفتر، افزونهٔ ZIP، و مشکلات `.env`.
2. `🩺 عیب‌یابی` (با تنظیماتِ درست) → ✅ هر خط 🟢/🟡/🔴 و **زیرِ** هر 🔴/🟡 یک ↳ راه‌حل.
   هیچ خطی «بررسی ناتمام» نباشد مگر واقعاً نیمی از بررسی‌ها اجرا نشده باشد (آن‌وقت 🔴 است،
   سبز نه). نبودِ افزونهٔ SKU روی سایت → 🟡 (خطا نه).
3. یک محصول بساز، بعد `📥 فایل متریک‌ها` → CSV بیاید. چک کن:

   - [ ] با **BOM** (`utf-8-sig`) باشد: در اکسل فارسی‌ها درست نشان داده شوند؛
   - [ ] یک سطر برای **هر** شمارنده باشد، حتی آن‌که صفرند (`ai_calls`, `ai_failures`,
         `outbox_queued`, `products_created`, `flow_abandoned`, `buttons_denied`, …);
   - [ ] `products_created` بعد از ساختِ یک محصول **یکی** اضافه شده باشد (این شمارنده در
         فاز ۸ یک‌بار «همیشه صفر» بود).
4. `/export_metrics` (به‌جای `/export-metrics` — خط تیره در دستور تلگرام مجاز نیست) → همان
   فایل.
5. `TISA_DRY_RUN=yes` و یک محصول بساز → ✅ شمارنده‌های **سمتِ فروشگاه**
   (`images_uploaded`, `sku_collisions`, …) تکان **نخورند** (تمرین نباید آمار را جعل کند).
6. یک جریان را ۱۵ دقیقه رها کن (`FLOW_TIMEOUT_SECONDS=900`) → ✅ پیامِ «جریان بسته شد» و

7. `🔄 ری‌استارت`: زیر supervisor ✅ «ری‌استارت شد» و بعد از بالا آمدن پیامِ تأیید؛ زیر
   systemd ✅ بگوید «این دکمه زیر supervisor کار می‌کند» (و دروغgo نگوید). اگر جریانِ
